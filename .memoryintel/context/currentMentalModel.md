docmanager-axi is a published, actively-used npm package (currently v1.5.0) that helps a user track HTML documents as version-lineage "families," the way git tracks commits - content-addressed, git-backed storage, a derived SQLite index, a CLI built on axi-sdk-js, and a local web UI whose reading pane is the primary way a user actually reads a tracked document. It ships as a single npm package with no bundler, syncs across machines via a user-provided git remote, and is designed to be driven primarily by a coding agent shelling out to its CLI.

Major capabilities beyond the original v1 scope, in build order: folders, cross-document link resolution, per-version text highlights, cascading highlights (2026-09-13 - capturing a new version carries a version's highlights forward, re-anchored by exact substring search, reversing the original per-version-highlights design's "never inherited" decision), and, also 2026-09-13, debounced automatic version capture - a burst of rapid saves a few seconds apart (an AI or human mid-edit) no longer each becomes its own permanent version. recordVersionIfChanged (store.js) now amends the current head's slot in place (same position in the supersedes chain, content/hash swapped, createdAt refreshed to now - a true trailing-edge debounce) when a save lands within settings.versionDebounceSeconds of the head's own createdAt, configurable as one of a fixed enum (5/10/15/20/30/45/60, default 20) via `docmanager settings set --version-debounce <seconds>` or the UI's Settings page. The family's ROOT version is deliberately never amended, regardless of timing - see decisions.md for why this specific guard exists (a real cross-machine sync bug the project's own test suite caught before it shipped, not a hypothetical).

This debounce feature required a project-wide test-suite fix, not just new tests: making it default-on with real wall-clock time broke ~26 pre-existing tests across cli.test.js, delete-version.test.js, diff.test.js, maintenance.test.js, reconcile.test.js, revert.test.js, snapshot.test.js, sync.test.js, and track.test.js, all of which record two-plus versions of the same family in quick real-time succession as scaffolding for an unrelated scenario. Fixed via a DOCMANAGER_VERSION_DEBOUNCE_MS env-var override in store.js (same "settings value, env var escape hatch" shape daemon.js's own DOCMANAGER_IDLE_TIMEOUT_MS already used) - test/helpers.js's useIsolatedHome() now zeroes it by default for every in-process test file, and test/cli.test.js's shared spawned-subprocess env sets it to "0" directly. store.test.js is the one file that explicitly deletes the override in its own beforeEach, since it's the file that tests the real debounce/amend mechanism itself (using node:test's built-in mock timers, `t.mock.timers.enable({ apis: ['Date'] })` - no new dependency, Node >=22 already required).

Architectural work in this project now consistently follows brainstorm -> written spec -> written implementation plan -> TDD task-by-task build -> manual Playwright verification for anything UI-facing, always landing via a feature branch + PR, never merged by the agent itself. Both of the 2026-09-13 features (cascading highlights, debounced capture) were bounded changes (extending one existing flow, not restructuring anything) built via brainstorm -> short in-chat design -> TDD, without a written spec/plan doc; the debounce feature's small Settings-page dropdown addition still got a real Playwright screenshot check (render, save, reload-persists) before being called done, consistent with this project's manual-verification discipline for anything UI-facing regardless of how small.
