docmanager-axi is a published, actively-used npm package (currently v1.2.1) that helps a user track HTML documents as version-lineage "families," the way git tracks commits - content-addressed, git-backed storage, a derived SQLite index, a CLI built on axi-sdk-js, and a local web UI whose reading pane is the primary way a user actually reads a tracked document. It ships as a single npm package with no bundler, syncs across machines via a user-provided git remote, and is designed to be driven primarily by a coding agent shelling out to its CLI.

Major capabilities beyond the original v1 scope, in build order: folders (a nested, synthetic-path-independent organization hierarchy, released in 1.2.0), cross-document link resolution (tracking a document also tracks whatever HTML it links to, and an `<a href>` between two tracked documents actually resolves and navigates inside the reading pane instead of being dead), and per-version text highlights (select text in the reading pane, mark it in one of 4 colors, scoped to the exact version it was made on - never inherited by a newer version). The latter two shipped together on branch `feature/cross-document-link-resolution` (off `main`, pushed with a PR being opened, not yet merged) - the second feature built directly on top of the first's own `handleContent()`/`postMessage` reading-pane infrastructure rather than duplicating it. Full mechanics and the three real bugs manual verification caught while building highlights (a wrong injection gate, a serve-route content-integrity issue affecting `families export`/`lavish`, and a script-timing bug) are in `progress.md`'s own sections for these - read those before touching `track.js`, `reconcile.js`, `server.js`'s `handleContent()`, `link-discovery.js`, `highlight-render.js`, or `app.js`'s reading-pane message listener.

Architectural work in this project now consistently follows brainstorm -> written spec -> written implementation plan -> TDD task-by-task build -> manual Playwright verification for anything UI-facing, always landing via a feature branch + PR, never merged by the agent itself. Manual browser verification specifically has caught real, non-hypothetical bugs multiple times now (not just this round) - it is treated as a required step for UI-touching work, not an optional nicety, and a temporary Playwright install is always fully removed afterward (confirmed via a clean `git status` on `package.json`/`package-lock.json`) rather than left as a standing dependency.

This project's own memory lives in Memory Intel (`.memoryintel/`), migrated off a hand-maintained `memory-bank/` folder. A real reliability gap found during that migration (nothing forced committing `.memoryintel/`'s own changes, especially from a worktree) was fixed upstream in the separate `memoryintel` package (now `memoryintel doctor`, released alongside a fix to `instructions.md` itself never spelling out the exact TOON update-plan syntax an agent needs - both real, user-facing gaps found and fixed in that sibling project this same era, not merely in docmanager-axi).
